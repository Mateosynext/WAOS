# WAOS Bot Creation — File-by-file deep audit

Date: 2026-04-26
Scope: complete bot creation flow from UI click to backend run, SSE recovery, readiness, apply and canary, including the legacy manual-create path guarded by `NEXT_PUBLIC_ENABLE_MANUAL_BOT_CREATE`.

## Production symptom verified

The provided production log showed repeated polling/stream reads against `/api/v1/ai/workflows/{run_id}/events` and `/livez`, but no matching `POST /api/v1/ai/bot-autopilot` start request. That supports the original diagnosis: at least one UI state could make the user click without creating a new run.

## Findings fixed in this pass

### Critical

1. `backend/app/ai_workflows/persistence.py`
   - Problem: `list_runs(conn, organization_ids=[])` treated an empty non-admin org list as falsy and returned all runs.
   - Risk: internal AI ops list could expose all workflow runs to a user with no org IDs.
   - Fix: distinguish `None` (super admin / unrestricted) from empty list (return no rows).

### High

2. `frontend/features/bot-studio/services/wizardAutopilotContract.ts`
   - Problem: legacy wizard AI proxy normalized object-shaped IDs with `String(value)`, producing `[object Object]`.
   - Risk: bad tenant/bot IDs could be sent downstream or produce confusing errors.
   - Fix: added object-aware extraction from `id`, `bot_id`, `organization_id`, `value`; objects without useful ID now become `null`/empty.

3. `backend/app/schemas/onboarding.py`
   - Problem: legacy `GuidedOnboardingAiPrefillRequest` and `GuidedOnboardingAiAutopilotRequest` did not share the defensive optional-ID normalization of the new `BotAutopilotRequest`.
   - Risk: `bot_id: {}` and rich select objects could still break the manual-create path.
   - Fix: added field validators for `organization_id`, `bot_id`, `vertical_id`, `subvertical`, and `primary_objective`.

4. `backend/app/schemas/onboarding.py`
   - Problem: legacy wizard autopilot still accepted `auto_apply` input.
   - Risk: stale or malicious clients could attempt to bypass the human apply gate in the legacy path.
   - Fix: force `auto_apply` to `False` in the request normalizer.

### Medium

5. `frontend/features/bot-studio/create/AiSetupAssistant.tsx`
   - Problem: legacy assistant allowed generation/autopilot with an empty or too-short description.
   - Risk: backend work could start with insufficient prompt data or appear to do nothing useful.
   - Fix: require 20 characters and show inline feedback.

6. `frontend/features/bot-studio/create/AiSetupAssistant.tsx`
   - Problem: rotating `setInterval` progress labels looked like real backend stages.
   - Risk: misleading UX during long runs.
   - Fix: replaced fake rotation with a single honest backend-running message; real step progress remains in the AI Command Center via SSE/polling.

### Low / hardening

7. `frontend/features/ai-command-center/useAiWorkflowStream.ts`
   - Problem: `workflow.keepalive` messages could be added to the event list.
   - Fix: keepalives update connection health but do not pollute the timeline.

8. `frontend/features/ai-command-center/AiRunTimeline.tsx`
   - Problem: stored keepalive events could appear in the UI if returned by snapshots.
   - Fix: timeline filters keepalive events.

9. `frontend/features/ai-command-center/AiCommandCenter.tsx`
   - Problem: non-JSON upstream proxy errors could throw a raw `JSON.parse` exception.
   - Fix: robust JSON parsing fallback gives the user the upstream text/status.

10. Release artifact hygiene
   - Problem: prior ZIP contained Python `__pycache__`/`.pyc` artifacts.
   - Fix: removed generated bytecode from the release tree.
